programdemos/moe-finetune/moe-finetune.xtl

Fine-tuning a tiny mixture-of-experts, each method in turn. The base (base.xtl, trained by train/base.xtl) classifies tokens of 4 kinds, each by its kind's own rule; the new task changes kind 3's rule. A method fine-tunes the base on 200 tokens of the new task (alone, or mixed with 200 of the old task's: replay), the base's own weights frozen, with LoRA adapters (rank 2) on some of its parts: the shared layer only; every expert, the router frozen; both; the two experts the new tokens use most; every expert with the router trained too; or a new expert, added with its own router row, trained alone. Each is measured by the new task's accuracy, the old task's (the kinds whose rule did not change: what fine-tuning must not break, 3 points the bar), the numbers it trains and their bytes, where the tokens are routed before and after, and how large each expert's update is.

A method is which parts train, (shared, experts, router, new): 1 or 0 for the shared layer's adapter, the base router's rows and the new expert (its weights and router row), a flag per base expert's adapter. The gradients of the cross-entropy go back through the experts and the router (MoE's g_rads and g_radsW, each token's two experts held fixed) and the shared layer (LoRA's g_rads, after tanh); every expert runs on every token here (d_ense, the same sum as the sparse c_ombine, faster at this size). A frozen part's gradient is 0, so Adam leaves it where it is. m g̲rads6 (xs, Ys): the model's loss on the tokens (xs, Ys) and its gradients for every part, (daS, dbS, dR, dW, dAs, dBs, loss).
