macro librarylibs/LoRA/src/LoRA.xtlm

LoRA's macro: an adapted layer written from a short spec -- its forward and backward passes, for LoRA or LoRA-FA

Import it with the library: "lo:" u_se< "LoRA" reaches LoRA.xtl's functions and this file's macro (X_eTaL MC11). Names with m: are macros; h: names are private to this file.

A macro is a function from the source text written left and right of its call to the source that replaces the call, before the program is compiled (X_eTaL MC10); xetal expand FILE shows the result. The spec names the adapter's arrays, its rank and what trains: "W A B s | r 3 | train A B". The arrays are the frozen W (m x n), A (r x n), B (m x r) and the scale s, as LoRA.xtl's adapter (W, A, B, s); "W" alone means "W A B s". The rank is a number or a name, and the expansion checks A's and B's shapes against it when the program runs. "train A B" is LoRA, "train B" is LoRA-FA (A frozen); nothing else trains. The expansion is ordinary code with no call to the library: the same formulas as lo:f_orward, lo:g_rads and lo:g_radsFA, written out for these names.

Adapters

ᵐa̲dapter< : Char -> Char -> Char

macro · line 113

An adapted layer from the spec on the right, as statements: the rank check, then the forward function and the backward function under the two names on the left ("u:f_wd u:b_wd"). The forward function takes the inputs (columns) and gives W x + s B (A x); the backward one takes the inputs and the loss's gradient at the output, (x, g), and gives (dA, dB, dx) for "train A B" (LoRA) or (dB, dx) for "train B" (LoRA-FA). The lambdas' own names are fresh ([]G_ENSYM, X_eTaL MC30), so a caller's array named x, g or b is not captured.
